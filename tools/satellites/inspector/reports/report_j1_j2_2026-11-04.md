## Leçons de pilotage (pour les prochaines exécutions — à remonter au FORMAT si arbitrées)

1. `arm.json` ET `scenario.json` exigent `protocol: "ts-drive/1"` — sans lui : refus
   (arm) / **status `ignored` silencieux** (scenario). Le runbook ne documente pas le champ
   protocol côté scenario (candidat finding de drift — hors périmètre inspector).
2. `seq` est monotone **au-delà des sessions** (le plancher reprend `result.json:ack_seq`) :
   un `seq` trop bas est ignoré sans trace ; viser haut (100000+) ou lire l'ack_seq d'abord.
3. `run_pipeline` : NE PAS passer `button` (le module map l'ajoute — `switch(module, …)`) ;
   passer `button` court-circuite la table et refuse le scénario si l'id n'est pas préfixé.
4. `set_inputs` : clés **namespacées** (`bulk-de-condition_col`) — l'allowlist refuse les ids
   nus (fail-closed honnête, message cite les clés refusées).
5. Les clients chromote zombie (driver tué, Chrome survit) **volent la sélection de session**
   (`selected_token` = dernier attaché) et re-prennent l'armement — tuer les Chrome headless
   avant d'armer ; un seul client à la fois.
6. Viewport chromote 992×1344 : les panneaux de droite (Table DE, QC) sont hors champ —
   régler 1920×1080 avant les captures verdict-complètes.
